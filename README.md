# TikTok Comment Analytics

**Audience Engagement, Sentiment, Topic and Behavioral Insights**

## Objective

This project analyses TikTok comments on Timor-Leste videos to understand how
audiences interact with videos through comments, comment likes and replies.
It answers:

- Which videos receive the most comments, likes, replies and engagement?
- What sentiment (Positive / Neutral / Negative) do the comments express?
- Which topics do audiences talk about?
- How are likes and replies related, and how does comment length relate to engagement?

## Dataset

Comments were collected with a TikTok comment scraper
(`data/tiktok_comments.json`, converted to `data/tiktok_comments.csv` by the
cleaning step). Each row is one comment (including replies to comments).

## Methods

| Method | Used for |
|---|---|
| **Pandas** | loading, cleaning, grouping and aggregating the data |
| **Descriptive statistics** | totals, averages, medians, distributions, top-N rankings |
| **VADER** | lexicon-based sentiment classification using the *compound* score (≥ 0.05 Positive, ≤ -0.05 Negative, otherwise Neutral). VADER is designed for English social-media text and also scores emoji. |
| **Supplementary lexicon** | ~30 sentiment words that appear in this dataset in Tetum, Indonesian, Portuguese and Spanish (e.g. *furak* = beautiful, *keren* = cool, *triste* = sad) added to VADER; two false matches (*tia*, *sin*) removed |
| **TF-IDF** | turns each comment into word weights (common words weigh less); English + multilingual stopwords removed |
| **NMF** | Non-negative Matrix Factorization groups comments into 5 topics from the TF-IDF matrix; topic names are only given when the top keywords clearly support them |
| **Correlation** | Pearson (linear) and Spearman (rank) correlation between comment likes and replies |
| **Visualization** | matplotlib (static charts in `output/visualization/`) and Plotly (dashboard) |
| **Streamlit** | interactive dashboard with a video filter and CSV download |

**Comment engagement score** = comment likes + replies. It is a comment-level
score, not TikTok's video engagement rate (views, shares and video likes are
not in the dataset).

### Limitations

- **Multilingual text.** Only a small part of the comments is English; most
  are Tetum, Indonesian, Spanish or Portuguese, or emoji only. The sentiment
  classifier assigns labels based on the selected lexicon method; comments
  with no recognised word or emoji are labelled Neutral. The share of these
  per language group is in `output/sentiment/sentiment_by_language.csv`.
- **Topics are exploratory.** NMF finds word patterns, not ground-truth
  categories. Emoji-only and very short comments have no topic words
  (`topic_id = 0`). The number of topics (5) is a starting point; see
  `output/topics/topic_k_evaluation.csv`.
- **One dominant video.** A single football-related video holds most of the
  comment likes, so totals and averages are strongly influenced by it.
- **Correlation is not causation.**
- Comments without text (stickers/GIFs) and repeated comments by the same
  user are kept (they are real comments) but flagged.

## Database

`08_database.py` loads the cleaned comments into a SQLite database,
`output/database/tiktok_comments.db`. It only needs `01_cleaning.py` to have
been run, and it rebuilds the database on every run.

| Object | Content |
|---|---|
| `videos` (table) | one row per video: `video_id`, `video_url`, `video_caption`, `video_label` |
| `comments` (table) | one row per comment, linked to `videos` by `video_id` |
| `cleaned_comments` (view) | both tables joined, same columns as `cleaned_comments.csv` |

True/False columns are stored as 1/0.

### User import and preprocessing

The dashboard also has an import flow for `.xlsx`, `.json`, and `.csv` files.
Each file must contain a comment column named `text`, `comment`, or `komentar`.
Date columns named `createdAt`, `created_at`, `date`, `tanggal`, or
`comment_date` are used for year and trend filters. Imported rows, original
text, cleaned text, tokens, filtered tokens, recognized dictionary tokens,
and dictionary-based sentiment are stored in the same SQLite database in the
`imports`, `imported_comments`, and `preprocessing_terms` tables. Imports are
kept when the legacy pipeline rebuilds its `videos` and `comments` tables.

StopWords are removed before sentiment scoring. Wordlist entries are assigned
the category `Positive` or `Negative` in the admin page; other categories are
not used for sentiment. Tokenizen is an editable vocabulary: tokens matching
it are recorded separately as recognized tokens. New imports use the current
dictionary contents; changing dictionaries does not retroactively reprocess
previous imports.

### Login and roles

Every dashboard page requires login. On first launch, set the Admin password
(minimum 8 characters); the salted PBKDF2 hash is stored in SQLite. Sign in
with username `admin`. Admins can create, edit, and remove User accounts from
**Manajemen User**. User passwords must be at least 10 characters. Admin sees
account management and preprocessing tools; User sees import and analysis
pages. Both roles can explore the visual analytics workspace.

For a deployment-managed Admin password, configure `admin_password` in the
project root `.streamlit/secrets.toml`, or set `TIKTOK_ADMIN_PASSWORD` in the
process environment. Do not commit a real password.

### Dashboard features

After each upload, the dashboard automatically cleans text, tokenizes it,
removes configured StopWords, records recognized Wordlist tokens, scores
sentiment, stores the results, and displays an immediate visual summary.
The User workspace includes an overview, sentiment analysis, sentiment
trends, interactive word cloud, comment explorer, and import history. Admins
can edit or delete imported comments, manage StopWords, Wordlist and the
Tokenizen vocabulary, and recalculate stored results after dictionary changes.

The imported sentiment page uses VADER plus the project's supplementary
Tetum, Indonesian, Portuguese, and Spanish lexicon. Admin Wordlist terms
extend VADER (Positive terms receive +2; Negative terms -2), after StopWord
removal. Labels use the same compound thresholds as the legacy pipeline:
`>= 0.05` Positive, `<= -0.05` Negative, otherwise Neutral. Admins can use
**Proses ulang semua data tersimpan** after changing preprocessing lists to
recalculate prior imports.

```sql
SELECT v.video_label, COUNT(*) AS comments, SUM(c.likes) AS likes
FROM comments c JOIN videos v ON v.video_id = c.video_id
GROUP BY v.video_id ORDER BY comments DESC;
```
